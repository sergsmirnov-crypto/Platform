# Дизайн-система

Визуальный ориентир — vanyanauchi.com. Обоснование ключевого отличия
(жёлтый как акцент, а не фон) — в [ADR-0006](adr/0006-visual-identity.md).

Посмотреть всё вживую: `pnpm dev` → http://localhost:3000/dev/ui

---

## Главное правило

Ни в одном компоненте не должно быть значений вида `#FFDD2D` или `14px`.
Только ссылки на токены из `src/ui/styles/tokens.css`.

Тогда изменить облик всей платформы можно правкой одного файла,
а не поиском по сотне компонентов.

## Цвета

Фирменные цвета одинаковы в обеих темах: жёлтый хорош и на белом, и на чёрном.

| Токен              | Назначение                              |
| ------------------ | --------------------------------------- |
| `--accent`         | Главные кнопки, активные состояния      |
| `--accent-soft`    | Подсветка маркером, индикатор прогресса |
| `--accent-content` | Текст на жёлтом — всегда чёрный         |
| `--danger`         | Разрушительные действия. Одно на экран  |
| `--surface`        | Фон страницы                            |
| `--surface-raised` | Карточки                                |
| `--surface-sunken` | Утопленные области, заполнители         |
| `--content`        | Основной текст                          |
| `--content-muted`  | Свойства, подписи                       |
| `--content-subtle` | Placeholder, третьестепенное            |
| `--border`         | Обычные границы                         |
| `--border-strong`  | Обводка вторичных кнопок                |
| `--focus-ring`     | Рамка фокуса клавиатуры                 |

### Правила контраста

Нарушать нельзя — иначе часть участников не сможет читать интерфейс.

- **На жёлтом только чёрный текст.** Белый на жёлтом даёт контраст 1,6:1
  при требуемых 4,5:1.
- **Красный только на белом или тёмном.** На жёлтом не читается.
- **Фокус клавиатуры виден всегда:** чёрная рамка на светлом,
  жёлтая на тёмном.

### Тёмная тема

Не инверсия светлой, а полноценный второй набор значений. Скорее всего
станет основной: люди занимаются вечером. Переключение — классом на `<html>`,
выбор человека сохраняется между визитами.

## Шрифты

| Роль              | Шрифт               | Где применяется                                    |
| ----------------- | ------------------- | -------------------------------------------------- |
| Заголовки         | **Onest** (700–800) | `h1`–`h3`, названия карточек, класс `font-display` |
| Интерфейс и текст | **Golos Text**      | всё остальное, по умолчанию                        |

Обе гарнитуры лежат в проекте и раздаются с нашего сервера, а не через
Google Fonts: скорость для участников из США и Сербии, независимость
от внешнего сервиса, отсутствие утечки IP пользователей на чужой CDN.

Onest используется только в заголовках — в мелком кегле он утомляет.

## Фирменный элемент: подсветка маркером

Взята из логотипа «Ваня, **научи!**». На платформе тот же приём работает
индикатором прогресса: жёлтая заливка проходит по названию разбора
по мере прохождения частей.

```tsx
<ProgressMarker value={0.5} label="3 из 6 частей">
  Nothing Else Matters
</ProgressMarker>
```

Приём из бренда становится функцией, а не украшением — этого у сайта-витрины
быть не могло.

Для статичной подсветки без прогресса есть класс `marker-highlight`.

Доступность: значение дублируется текстом и атрибутами для скринридера,
поэтому прогресс понятен и без цвета.

## Компоненты

Все импортируются из `@/ui`.

### Кнопка

```tsx
<Button>Продолжить</Button>
<Button variant="secondary">Табы</Button>
<Button variant="ghost">Отмена</Button>
<Button variant="danger">Удалить разбор</Button>
```

Иерархия повторяет сайт-витрину: главное действие — жёлтая заливка,
второстепенное — обводка. Ровно как пара «Купить табы / Видео аранжировки».

**Главное действие на экране должно быть одно.** Если их два, человек
не понимает, чего от него хотят.

Высота не меньше 44 пикселей: платформой пользуются с телефона,
часто с гитарой в руках.

### Карточка

```tsx
<Card>
  <CardBody>
    <CardMeta>Metallica</CardMeta>
    <CardTitle>Nothing Else Matters</CardTitle>
    <CardActions>…</CardActions>
  </CardBody>
</Card>
```

### Метки, поля, прочее

| Компонент                             | Назначение                                                           |
| ------------------------------------- | -------------------------------------------------------------------- |
| `Badge`                               | Уровень, строй, состояние публикации                                 |
| `Input`, `Textarea`, `Label`, `Field` | Формы. `Field` собирает подпись, подсказку и ошибку                  |
| `ProgressMarker`                      | Фирменный индикатор прогресса                                        |
| `Skeleton`                            | Заполнитель на время загрузки                                        |
| `EmptyState`                          | Пустой экран с приглашением к действию                               |
| `Avatar`                              | Фотография участника, размеры `sm`/`md`/`lg`/`xl`. Без фото — силуэт |
| `Dialog`                              | Модальное окно                                                       |
| `ImageCropper`                        | Выбор квадратного кадра из изображения                               |
| `PageHeader`                          | Надзаголовок, заголовок, действия                                    |
| `PillLink`                            | Ссылка-таблетка: фильтр, подборка, уровень разбора, номер страницы   |
| `PropertyList`                        | Пары «название — значение»: строй, темп, тональность                 |
| `Wave`                                | Фирменная волна. Дозированно: вход, главная, «подписка закончилась»  |

### Плеер

Единственный компонент страниц разбора, урока и эфира, работающий
в браузере. Всё
остальное собирается на сервере; плееру браузер нужен по существу —
перемотка к части, скорость и полноэкранный режим ссылками не делаются.

Компонент не знает названия видеохостинга: адрес, водяной знак
и оглавление приходят готовыми из `shared/video`. Смена хостинга заменит
файл поставщика, а не этот компонент.

Водяной знак задаётся настройками плеера, а не адресом, поэтому убрать
его правкой строки в браузере нельзя.

### Оглавление записи эфира

Список «название плюс время» рядом с плеером. Нажатие перематывает уже
загруженный ролик — страница не перезагружается, буфер и позиция
прокрутки сохраняются. Те же пункты уходят на дорожку плеера, поэтому
работают и в полноэкранном режиме.

Компонент ничего не решает сам: обработчик перехода приходит сверху.
Без него список остаётся просто списком — так он показывается участнику
без подписки, которому оглавление видно, а запись нет.

### Редактор оглавления

Строка на пункт: время текстом, название, крестик. Порядок не задаётся —
список выстраивается по времени при сохранении. Enter в последней строке
добавляет следующую, поэтому оглавление набирается с клавиатуры целиком.
Ошибки (название без времени, два пункта на одну секунду) показываются
рядом со строкой, а не после нажатия «Сохранить»
([ADR-0021](adr/0021-manual-chapter-timecodes.md)).

### Время эфира

Время клуба с пометкой «МСК» пишет сервер; строка «у вас — 19:00»
дописывается в браузере и только при настоящем расхождении часов
([ADR-0020](adr/0020-stream-time-and-reminders.md)).

### Ссылка-таблетка

```tsx
<PillLink href={...} active={isFilterOn}>Drop D</PillLink>
<PillLink href={...} current={isOpenLevel} size="md">Уверенный</PillLink>
```

Всё, что переключается этим элементом, живёт в адресной строке. Отсюда
бесплатно получается работающая кнопка «назад», возможность отправить
ссылку на «продвинутый разбор Nothing Else Matters» и работа при
выключенном JavaScript.

**Три состояния, а не два.** `active` — значение выбрано человеком
(фильтр), жёлтая заливка. `current` — человек находится здесь (открытый
уровень, текущая страница), подсветка сдержаннее. Путать нельзя: жёлтым
на экране горит то, что человек включил сам.

### Список свойств

```tsx
<PropertyList items={[{ label: 'Строй', value: 'Drop D' }]} />
<PropertyList items={...} layout="stacked" />
```

Размечен тегом `<dl>`: пара «название — значение» так и объявляется
экранным диктором, а на странице разбора их до пяти подряд. Пустые
значения отсеиваются внутри — у песни редко заполнено всё, и строка
«Каподастр — не указан» занимает место, ничего не сообщая.

### Модальное окно и кадрирование

`Dialog` построен на элементе `<dialog>` браузера, а не на своей разметке
с наложением. Браузер сам запирает фокус клавиатуры внутри окна, отключает
содержимое под ним для чтения с экрана, закрывает по Esc и держит окно
поверх всего без борьбы со слоями. Расплата — окно нельзя анимировать
так же свободно, как обычный блок.

```tsx
<Dialog
  open={open}
  onClose={() => setOpen(false)}
  title="Кадрирование"
  footer={<Button onClick={save}>Сохранить</Button>}
>
  …
</Dialog>
```

`ImageCropper` отдаёт наружу только координаты кадра — само изображение
он не трогает. Поэтому годится и для фотографии профиля (`round`),
и для обложек разборов. Управление тремя способами: перетаскивание,
щипок двумя пальцами, ползунок со стрелками клавиатуры. Последний
обязателен: без него кадрирование недоступно тем, кто не пользуется мышью.

Вся математика вынесена в `src/ui/lib/crop-geometry.ts` и покрыта тестами.
Правка кадратора начинается с них: ошибка в вычислении рамки выглядит
как срезанный край фотографии и глазами не ловится.

### Зона загрузки файла

`FileDrop` — только внешний вид: сама ничего не отправляет и о хранилище
не знает. Отправку делает тот, кто её поставил. Поэтому один компонент
годится и для табов разбора, и для будущего конспекта урока, и для
вложения к эфиру.

```tsx
<FileDrop
  accept={UPLOAD_ACCEPT}
  label="Перетащите файл сюда"
  hint="PDF, Guitar Pro, аудио, картинки"
  busy={busy}
  progress={progress}
  onFile={(file) => void upload(file)}
/>
```

Перетаскивание есть, но оно **не единственный способ**: вся зона
одновременно является кнопкой, и нажатие открывает обычный выбор файла.
Перетащить файл удобно за столом и невозможно с телефона.

Отправка — `uploadFile` из `@/ui`, на устаревшем `XMLHttpRequest`.
Причина одна: прогресс отправки, которого `fetch` до сих пор не даёт.
Для файла на двадцать мегабайт это разница между ползущей полосой
и кнопкой, которая «ничего не делает», — после чего её нажимают второй
раз и получают два одинаковых таба.

### Редактор блоков

`manage/course/_components/block-editor.tsx` — обратная сторона решения
о собственном формате конспекта ([ADR-0018](adr/0018-lesson-content-blocks.md)).
Куратор не печатает свободный текст с форматированием, а собирает урок
из готовых видов блоков.

Добавить вид блока — это одна ветка в `BlockFields`, одна строка
в списке `ADDABLE` и один компонент в отрисовке. Ни сервер, ни база
не меняются.

Блоки, которые нельзя набрать текстом (картинка, видео, связанный
разбор), редактор показывает, но не даёт править — и **не теряет
при сохранении**. Молча выбрасывать чужое содержимое хуже, чем честно
сказать «пока не редактируется».

### Конспект урока

Каждый вид блока — свой компонент в
`learn/course/[module]/[lesson]/_components/lesson-content.tsx`.
Никакой разметки из базы: в `content` лежат данные, и превратить их
в страницу — работа React ([ADR-0018](adr/0018-lesson-content-blocks.md)).

Две детали, которые легко потерять при правке:

- **Совет и предупреждение оформлены по-разному** и разными значками.
  Они говорят разное: «так будет проще» и «так вы навредите себе».
  Одинаковое оформление приводит к тому, что второе перестают замечать.
- **Аккордовая сетка не переносится по строкам,** а прокручивается
  вбок. Сетка из шести строк, сложенная пополам на узком экране,
  перестаёт быть сеткой.

### Подсветка найденного

`Highlight` подсвечивает слова из поискового запроса тем же фирменным
маркером, что и прохождение разбора. Приём из логотипа работает
и украшением, и указанием: глаз сразу находит, за что зацепился поиск.

```tsx
<Highlight text={song.title} terms={terms} />
```

Подсвечивается **начало слова**, а не любое вхождение: заливка «ка»
внутри «Пачка» при поиске «Кино» выглядела бы как ошибка. Правило то же,
что у самого поиска.

У PostgreSQL есть `ts_headline`, умеющий вернуть текст с готовой
разметкой. Мы им не пользуемся: это HTML из базы, и вставить его
можно только через `dangerouslySetInnerHTML`. Заводить такую дверь ради
жёлтой заливки — плохой размен, даже когда содержимое сейчас безопасно.

### Обложки разборов

Обложек альбомов у платформы нет и взяться им неоткуда: скачивать
их из открытых источников — это чужие права на изображения в закрытом
платном сервисе, а просить кураторов подобрать 280 картинок вручную —
это работа, которой они заниматься не станут.

`SongCover` рисует обложку типографски: крупное название на цветном
поле, цвет устойчиво выводится из адреса песни. Ничего не стоит,
не зависит от чужих сервисов, никогда «не загружается» и выглядит
фирменно — тот же приём, что на сайте-витрине.

Побочная выгода оказалась не меньше главной: каталог из ста карточек
весит столько же, сколько пустая страница.

### Верх страницы

**Правило: каждая страница закрытой зоны начинается с `PageIntro`.**
Собственные заголовки на страницах не пишутся.

```tsx
<PageIntro
  title="Разборы"
  description="Библиотека разборов клуба"
  actions={<LinkButton href={...}>Новый разбор</LinkButton>}
/>
```

Компонент сам рисует навигационную цепочку: она строится из адреса
страницы, а не задаётся руками. Заголовок страницы становится последним
звеном цепочки — поэтому он всегда совпадает с тем, что человек видит
в пути.

Названия разделов лежат в `src/app/app/_lib/breadcrumbs.ts` и сверяются
с меню тестом. Переименование раздела в меню автоматически требует
правки реестра, иначе сборка не пройдёт.

Поля страницы (отступы от краёв) заданы в разметке закрытой зоны — на
страницах их задавать не нужно.

### Элементы оболочки

Живут не в дизайн-системе, а рядом со страницами
(`src/app/app/_components/`): они знают о правах и режимах, а `ui/`
о бизнес-логике знать не должно.

| Компонент       | Назначение                                                            |
| --------------- | --------------------------------------------------------------------- |
| `Sidebar`       | Боковое меню на компьютере, с раскрытием подразделов активного пункта |
| `TabBar`        | Нижняя панель на телефоне, пять разделов                              |
| `AppHeader`     | Шапка: название, состояние подписки, меню профиля                     |
| `ProfileMenu`   | Выпадающее меню: профиль, настройки, режим просмотра, тема, выход     |
| `PreviewBanner` | Полоса «глазами участника» с кнопкой возврата                         |
| `PreviewToggle` | Кнопка включения и выключения режима. Вид задаётся снаружи            |

**Полоса режима просмотра.** Жёлтый фон, чёрный текст, высота 2,5rem.
Высота задана переменной `--banner-h` в разметке закрытой зоны — её же
используют шапка и боковое меню, чтобы сдвинуться вниз. Держать одно
и то же число в трёх файлах нельзя: при первой правке они разъедутся.

Полоса обязана быть заметной. Человек, забывший, что включил режим,
решит, что платформа сломалась: пропали кнопки, исчезли черновики, из
меню ушёл целый раздел.

## Тексты интерфейса

Слова — такой же материал, как отступы и цвет.

- **Кнопка называет действие, а не форму:** «Сохранить изменения»,
  а не «Отправить». Название действия не меняется по ходу:
  кнопка «Опубликовать» даёт сообщение «Опубликовано».
- **Ошибка объясняет, что не так и что делать.** Не извиняется,
  не пишет «произошла ошибка».
  Правильно: «Укажите исполнителя — по нему работает поиск в каталоге».
- **Пустой экран приглашает к действию,** а не сообщает о пустоте.
- **Вещи называются так, как их видит участник,** а не так, как устроена
  система: «уведомления», а не «настройка вебхуков».

## Ограничения

- Диалоги, выпадающие меню и боковые панели появятся на Этапе 3,
  вместе с навигацией. Тогда же будет добавлен Radix.
- Витрина `/dev/ui` заменяет Storybook. Если компонентов станет больше
  пятидесяти, стоит вернуться к вопросу.
- Мобильные размеры проверены вёрсткой, но не на живых устройствах.
