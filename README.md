# Гитарный клуб — веб-платформа

Закрытая платформа гитарного клуба: разборы песен, онлайн-курс, записи эфиров,
профили участников. Вход — через Telegram, доступ — по подписке.

## Запуск за 10 минут

Нужны **Node.js 22** и **Docker**. Если pnpm нет:

```bash
corepack enable pnpm
```

Дальше:

```bash
cd guitar-club
pnpm install           # установка зависимостей
docker compose up -d   # база данных
pnpm demo              # настройки, таблицы, справочники, демо-содержимое
pnpm dev               # запуск
```

Открыть <http://localhost:3000/dev/login> и войти под «Владелец».

Вход через Telegram на `localhost` не работает — виджет привязан
к настоящему домену. Для осмотра есть служебный вход `/dev/login`,
которого в производственной сборке не существует.

Подробная инструкция и решение частых проблем: [docs/SETUP.md](docs/SETUP.md)

## Структура проекта

```
src/
├─ app/       маршруты и страницы Next.js — тонкий слой
├─ modules/   бизнес-логика, по одному модулю на предметную область
├─ shared/    инфраструктура: БД, конфигурация, логи, ошибки, внешние сервисы
├─ ui/        дизайн-система: цвета, шрифты, базовые компоненты
└─ worker/    фоновые задачи (отдельный процесс)

docs/         документация проекта — начинать чтение с ARCHITECTURE.md
drizzle/      миграции базы данных
```

### Настройки

Все настройки задаются переменными окружения в файле `.env`
(образец со всеми переменными и пояснениями — `.env.example`).

Значения проверяются один раз, при запуске. Если чего-то не хватает,
приложение **не запускается** и печатает, какой переменной не хватает
и где её взять. На боевом сервере процесс при этом завершается: система
развёртывания видит неудачу и оставляет работать предыдущую версию.

Проверить настройки, не запуская приложение:

```bash
pnpm env:check
```

Правила, которые нельзя нарушить на боевом сервере: проверка входа включена,
адрес по `https`, задано подключение к базе. Полный список — в
`src/shared/config/env.schema.ts`.

Продуктовые значения (срок сессии, льготный период подписки, размер страницы
каталога) живут отдельно, в `src/shared/config/app.config.ts`: они одинаковы
на всех серверах и являются частью продукта, а не развёртывания.

### Адреса страниц

Все адреса собраны в одном месте — `src/shared/routes/routes.ts`.
В коде ссылки пишутся только через него:

```tsx
<Link href={routes.app.learn.song(song.slug)}>{song.title}</Link>
```

Строк вида `'/app/learn/songs'` прямо в компонентах быть не должно:
переименование раздела тогда превращается в правку одного файла,
а опечатка в адресе — в ошибку сборки, а не в битую ссылку.

Полная карта адресов доступна при локальной разработке:
http://localhost:3000/dev/routes

### Дизайн-система

Все элементы платформы — на витрине http://localhost:3000/dev/ui
(только при локальной разработке).

Цвета, шрифты и размеры заданы токенами в `src/ui/styles/tokens.css`.
В компонентах не должно быть значений вида `#FFDD2D` — только ссылки
на токены. Подробнее: [docs/COMPONENTS.md](docs/COMPONENTS.md)

**Правило зависимостей:** `app → modules → shared`. Только вниз, без исключений.
Оно проверяется автоматически линтером, нарушение — ошибка сборки.

## Правила работы с кодом

**Коммиты** — в формате Conventional Commits:

```
feat(auth): implement telegram authentication
fix(songs): correct level filter on empty catalog
docs(architecture): describe permission model
chore(deps): update next to 16.3.1
```

Допустимые области перечислены в `commitlint.config.mjs`. Неправильное
сообщение коммита не пройдёт — это проверяется автоматически.

**Перед коммитом** автоматически запускаются линтер и форматирование
для изменённых файлов. Ничего делать вручную не нужно.
