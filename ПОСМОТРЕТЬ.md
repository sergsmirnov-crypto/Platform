# Посмотреть платформу на своём компьютере

Инструкция для человека без технического опыта.
Ничего настраивать, никаких ботов подключать, никакие материалы загружать
не нужно. Задача одна: увидеть платформу целиком своими глазами.

**Время:** 20–30 минут, из них большая часть — ожидание установки.
**Что установится на компьютер:** две программы, обе бесплатные
и общеупотребимые. Обе удаляются штатно, если платформа не понравится.

---

## Часть 1. Подготовка (один раз)

### Шаг 1. Установить Node.js

Это среда, в которой работает платформа. Без неё компьютер не понимает,
что за файлы вы ему дали.

1. Откройте <https://nodejs.org>
2. Скачайте версию с пометкой **LTS** (она слева, «рекомендуется большинству»)
3. Запустите скачанный файл и нажимайте «Далее» до конца, ничего не меняя

> **Важно:** нужна версия **22 или новее**. На сайте LTS сейчас старше
> не бывает, но если вы устанавливали Node.js когда-то раньше — проверьте
> версию на шаге 3 части 2 и при необходимости переустановите.

### Шаг 2. Установить Docker Desktop

В нём будет работать база данных — место, где платформа хранит участников,
разборы и прогресс. Отдельно ставить базу данных не нужно: Docker сделает
это сам.

1. Откройте <https://www.docker.com/products/docker-desktop/>
2. Скачайте версию для своей системы (Windows или Mac — выберите Apple Silicon,
   если ваш Mac 2021 года или новее)
3. Установите и **запустите** программу
4. Дождитесь, пока значок китёнка в верхней (Mac) или нижней (Windows)
   панели перестанет мигать — это значит, что Docker готов

> Docker должен быть **запущен** всё время, пока вы смотрите платформу.
> Если вы перезагрузите компьютер, его нужно будет открыть заново.

### Шаг 3. Открыть терминал

Терминал — окно, где команды набираются текстом. Пугаться нечего:
вы будете копировать готовые строки и нажимать Enter.

- **Windows:** нажмите «Пуск», наберите `PowerShell`, откройте его
- **Mac:** нажмите Cmd+Пробел, наберите `Терминал`, откройте его

## Часть 2. Запуск

### Шаг 1. Распаковать проект

Распакуйте полученный архив, например в папку «Документы».
Внутри будет папка `guitar-club`.

### Шаг 2. Перейти в папку проекта

В терминале наберите `cd ` (три знака: c, d, пробел), затем **перетащите
папку `guitar-club` мышкой прямо в окно терминала** — путь подставится сам.
Нажмите Enter.

```bash
cd путь/к/guitar-club
```

### Шаг 3. Проверить, что Node.js установлен

```bash
node -v
```

Должно ответить `v22.` и дальше цифры. Если ответ начинается с `v20`
или меньше — вернитесь к шагу 1 части 1.

### Шаг 4. Включить менеджер пакетов

```bash
corepack enable pnpm
```

Если Windows ответит ошибкой про права — закройте PowerShell, откройте
заново через правую кнопку → «Запуск от имени администратора», и повторите.

### Шаг 5. Установить зависимости платформы

```bash
pnpm install
```

Это самый долгий шаг: 2–5 минут. По экрану побегут строки — так и должно быть.
Ждите, пока не вернётся строка ввода.

### Шаг 6. Запустить базу данных

```bash
docker compose up -d
```

Ответ вида `Container guitar-club-db Started` означает успех.
Если написано `Cannot connect to the Docker daemon` — не запущен Docker Desktop
(шаг 2 части 1).

### Шаг 7. Подготовить платформу — одной командой

```bash
pnpm demo
```

Команда сама создаст файл настроек, придумает секретный ключ, создаст таблицы
в базе и заполнит платформу демонстрационным содержимым: 9 разборов песен,
курс из 3 модулей и 8 уроков, 5 эфиров, карточки кураторов, метки и фильтры.

В конце она напишет, что делать дальше. Правильный ответ — шаг 8.

### Шаг 8. Запустить платформу

```bash
pnpm dev
```

Через несколько секунд появится строка `Ready`. **Это окно терминала
нужно оставить открытым** — пока оно работает, работает и платформа.

### Шаг 9. Войти

Откройте в браузере:

**<http://localhost:3000/dev/login>**

Вы увидите список участников и кнопку «Войти» напротив каждого.
Нажмите «Войти» напротив **«Владелец»** — это учётная запись с полными правами.

> **Почему не через Telegram?** Кнопка входа Telegram работает только
> на настоящем домене — на своём компьютере она физически не может работать.
> Поэтому в проекте есть служебный вход, который открывает сессию напрямую.
> В боевой сборке этой страницы не существует вовсе — она отдаёт «404».

Начните с главной и просто ходите по меню. Ниже — карта того,
что есть, чтобы вы ничего не пропустили.

Попробуйте главное: откройте разбор как участник, найдите кнопку

Ещё попробуйте в меню профиля переключатель **«Смотреть как участник»**:
все управляющие кнопки и черновики исчезнут, вы увидите платформу глазами

### Проверьте телефон

Откройте платформу на телефоне: в терминале рядом с `Local` написан адрес
`Network` вида `http://192.168.0.5:3000` — наберите его в браузере телефона,
подключённого к тому же Wi-Fi. Появится нижняя панель на пять пунктов,
а не боковое меню.

## Чего в демо-режиме нет

Это не поломки, а сознательно отключённые вещи. Каждая включается
на этапе настоящего запуска.

| Чего нет                   | Почему                                 | Что видно вместо                             |
| -------------------------- | -------------------------------------- | -------------------------------------------- |
| **Видео не проигрывается** | Видеохостинг не подключён и не оплачен | Место плеера с пояснением                    |
| **Вход через Telegram**    | Виджет не работает на `localhost`      | Служебный вход `/dev/login`                  |
| **Настоящие подписки**     | Бот не привязан к каналу               | У владельца доступ выдан вручную             |
| **Уведомления в Telegram** | Бота нет                               | Уведомления накапливаются в самой платформе  |
| **Ваши материалы**         | Не загружались                         | 9 демонстрационных разборов вместо ваших 186 |

Смысл демо — оценить продукт: структуру, экраны, удобство, тексты.
Именно это и работает по-настоящему.

## Как закончить и как вернуться

**Остановить:** в окне терминала нажмите `Ctrl+C`. Затем, если хотите
освободить память, остановите базу:

```bash
docker compose down
```

**Вернуться позже:** запустите Docker Desktop, откройте терминал,
перейдите в папку проекта и выполните два шага — база и платформа:

```bash
docker compose up -d
pnpm dev
```

Заново `pnpm install` и `pnpm demo` не нужны: всё уже сделано, содержимое
и ваши правки сохранились в базе.

**Начать содержимое с чистого листа** (если наэкспериментировали):

```bash
pnpm db:reset
pnpm demo
```

## Если что-то не получилось

Сначала три самые частые причины — они закрывают почти все случаи:

| Что видите                                 | Почему                               | Что делать                                              |
| ------------------------------------------ | ------------------------------------ | ------------------------------------------------------- |
| `Cannot connect to the Docker daemon`      | Docker Desktop не запущен            | Открыть Docker Desktop, дождаться готовности, повторить |
| `command not found: pnpm`                  | Не выполнен шаг 4                    | `corepack enable pnpm`                                  |
| `ECONNREFUSED ... 5433`                    | База не поднята                      | `docker compose up -d`                                  |
| `port 3000 is already in use`              | Платформа уже запущена в другом окне | Закрыть то окно или перезагрузить компьютер             |
| Страница белая, в терминале красные строки | Настоящая ошибка                     | См. ниже                                                |

**Если это настоящая ошибка:** скопируйте из терминала **весь красный текст**
целиком, включая строки после слов `Error:` — и пришлите мне.
Не пересказывайте («не работает главная») и не обрезайте: в этих строках
написано, какой файл и какая строка виноваты. С полным текстом ошибку
чаще всего видно сразу; без него приходится угадывать.

Полезно приложить: на каком шаге инструкции остановились, Windows или Mac,
и что ответила команда `node -v`.
