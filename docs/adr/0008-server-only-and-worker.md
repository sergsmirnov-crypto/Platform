# ADR-0008. Защита `server-only` и отдельный процесс задач

**Статус:** принято · **Дата:** 2026-08

## Контекст

Серверные модули помечены пакетом `server-only`. Это предохранитель:
попытка использовать код с секретами в браузере становится ошибкой сборки,
и токен бота не может утечь на клиент по невнимательности.

При первом запуске процесса фоновых задач выяснилось, что этот же
предохранитель ломает запуск: `server-only` рассчитан на сборщик Next.js
и вне его выбрасывает ошибку. Процесс задач работает отдельно, через `tsx`.

## Варианты

**А. Убрать `server-only` из модулей, используемых процессом задач.**
Теряется защита ровно там, где лежат самые чувствительные вещи:
подключение к базе, настройки, токены.

**Б. Продублировать код для процесса задач.** Две копии бизнес-логики,
которые неизбежно разойдутся.

**В. Запускать процесс задач с условием разрешения модулей `react-server`.**

## Решение

Вариант В:

```
tsx --conditions=react-server src/worker/index.ts
```

Пакет `server-only` устроен так, что при этом условии подставляется пустая
реализация — ровно то, что делает сборщик Next.js на сервере.

## Последствия

- Флаг обязателен в командах `worker` и `worker:dev`, а также в команде
  запуска контейнера задач. Без него процесс не стартует с невнятной ошибкой.
- Защита сохраняется полностью: в браузерном коде секретные модули
  по-прежнему невозможны.
- Отдельно понадобился файл-загрузчик `src/worker/index.ts`: переменные
  окружения нужно прочитать до того, как загрузится модуль, который их
  читает, а импорты в JavaScript выполняются раньше кода.
