# Запуск проекта

Инструкция для человека, который открыл репозиторий впервые.
Должно занять около десяти минут.

---

## Что нужно установить

| Программа                                                         | Зачем                      | Как проверить       |
| ----------------------------------------------------------------- | -------------------------- | ------------------- |
| [Node.js 22](https://nodejs.org)                                  | На нём работает приложение | `node -v` → `v22.x` |
| [Docker Desktop](https://www.docker.com/products/docker-desktop/) | В нём работает база данных | `docker -v`         |
| [Git](https://git-scm.com)                                        | Скачать проект             | `git -v`            |

pnpm отдельно ставить не нужно — он включается одной командой:

```bash
corepack enable pnpm
```

---

## Первый запуск

```bash
# 1. Скачать проект
git clone <адрес репозитория>
cd guitar-club

# 2. Установить зависимости
pnpm install

# 3. Создать файл настроек
cp .env.example .env

# 4. Поднять базу данных
docker compose up -d

# 5. Проверить, что настройки в порядке
pnpm env:check

# 6. Создать таблицы и заполнить справочники
pnpm db:migrate
pnpm db:seed

# 7. Запустить приложение
pnpm dev
```

Открыть http://localhost:3000

Карта всех страниц (доступна только при локальной разработке):
http://localhost:3000/dev/routes

## Что где живёт

| Что         | Где                                                     |
| ----------- | ------------------------------------------------------- |
| Приложение  | http://localhost:3000 — запускается командой `pnpm dev` |
| База данных | в Docker, порт **5433**                                 |
| Настройки   | файл `.env` (в git не попадает)                         |

**Почему база на порту 5433, а не 5432.** Если PostgreSQL уже стоял
на компьютере раньше, он занимает 5432. Нестандартный порт снимает конфликт
и позволяет держать несколько проектов одновременно.

**Почему приложение запускается не в Docker.** При правке кода страница
обновляется мгновенно только когда приложение работает напрямую.
В контейнере это заметно медленнее. В Docker живёт только то,
что не хочется ставить на свой компьютер.

---

## Ежедневная работа

```bash
docker compose up -d   # поднять базу (один раз после перезагрузки)
pnpm dev               # запустить приложение
```

Фоновые задачи (сверка подписок, уведомления) живут в отдельном процессе.
Для большинства задач разработки он не нужен, но если нужен — во втором окне:

```bash
pnpm worker:dev
```

Перед отправкой кода в репозиторий:

```bash
pnpm check             # форматирование, линтер, типы, тесты
```

## Если что-то не работает

**`pnpm dev` пишет об ошибке настроек.**
Запусти `pnpm env:check` — он покажет, какой переменной не хватает
и где её взять.

**Приложение не видит базу.**
Проверь, что контейнер работает: `docker compose ps`.
Должно быть состояние `healthy`. Если нет — `docker compose logs postgres`.

**Порт 3000 занят.**
Запусти на другом: `PORT=3001 pnpm dev`.

**Нужно начать базу с чистого листа.**
Команда удалит все данные без возможности восстановления:

```bash
docker compose down -v
docker compose up -d
```

## Команды

| Команда                           | Что делает                           |
| --------------------------------- | ------------------------------------ |
| `pnpm dev`                        | Запуск для разработки                |
| `pnpm build`                      | Производственная сборка              |
| `pnpm check`                      | Все проверки разом                   |
| `pnpm env:check`                  | Проверка файла `.env`                |
| `docker compose up -d`            | Поднять базу данных                  |
| `docker compose down`             | Остановить базу (данные сохраняются) |
| `docker compose logs -f postgres` | Смотреть журнал базы                 |
