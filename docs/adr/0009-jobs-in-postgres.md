# ADR-0009. Очередь задач внутри PostgreSQL

**Статус:** принято · **Дата:** 2026-08

## Контекст

Нужны фоновые задачи: ночная сверка подписок с Telegram, обработка вебхуков,
отправка уведомлений, обработка загруженного видео.

Привычное решение — Redis плюс библиотека очередей. В PRD v0.1 так
и планировалось.

## Решение

`pg-boss` — очередь, живущая в той же PostgreSQL, в отдельной схеме.

## Обоснование

При 250 участниках речь идёт о сотнях задач в сутки. Разница в скорости
между Redis и PostgreSQL на таком объёме незаметна, а разница в сложности
эксплуатации существенна: Redis — это ещё один сервис, который надо поднять,
обновлять, следить за его памятью и чинить, когда он упадёт ночью.

Побочная выгода важнее скорости: задача и данные, которые она меняет,
попадают в одну резервную копию. При восстановлении из бэкапа не возникает
ситуации, когда очередь помнит о задачах, которых в базе уже нет.

## Последствия

- Задачи создают нагрузку на ту же базу, что и сайт. При текущих объёмах
  это доли процента.
- Потолок — примерно несколько тысяч задач в минуту. До него нам далеко;
  если приблизимся, переезд на отдельную очередь будет оправдан,
  а интерфейс постановки задач останется тем же.
- Задачи можно смотреть обычным SQL-запросом, без отдельного инструмента.
