# Эксплуатация

Документ для того, кто отвечает за работающую платформу.
Написан так, чтобы им мог воспользоваться и не разработчик.

| Что              | Где взять                   | Примерная цена            |

без этого платформа не узнает об изменениях подписки.

## 2. Развёртывание

### Через Dokploy (рекомендуется)

Dokploy — панель управления на вашем сервере. Она берёт на себя HTTPS,
сертификаты, обновление версий и откат.

1. Установить Dokploy на VPS (одна команда с их сайта).
2. Создать приложение, указать репозиторий проекта.
3. В разделе переменных окружения задать всё из `.env.example`.
4. Указать домен — сертификат выпустится автоматически.
5. Нажать «Развернуть».

Обновление версии: `git push` в основную ветку, дальше Dokploy сам.

### Напрямую

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

## 3. Обязательные настройки боевого сервера

Приложение **не запустится**, если что-то из этого не так:

| Переменная                                    | Требование                                             |
| --------------------------------------------- | ------------------------------------------------------ |
| `AUTH_ENABLED`                                | Обязательно `true`. Иначе закрытая зона откроется всем |
| `NEXT_PUBLIC_APP_URL`                         | Обязательно начинается с `https://`                    |
| `DATABASE_URL`                                | Задано                                                 |
| `SESSION_SECRET`                              | Не короче 32 символов                                  |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` | Заданы                                                 |

Сгенерировать секреты:

```bash
openssl rand -base64 32   # SESSION_SECRET
openssl rand -hex 32      # TELEGRAM_WEBHOOK_SECRET
```

Проверить настройки, не запуская приложение: `pnpm env:check`

**Если настройки неверны, контейнер завершится с объяснением в журнале.**
Это сделано намеренно: система развёртывания увидит неудачу и оставит
работать предыдущую версию.

### Расширение базы для поиска

Миграция шага 5.7 выполняет `CREATE EXTENSION IF NOT EXISTS pg_trgm` —
без него поиск по разборам не переживёт опечатку. Создание расширения
требует прав суперпользователя базы.

На нашем PostgreSQL в Docker это проходит само: приложение подключается
пользователем `postgres`. Если базу когда-нибудь переносят к стороннему
поставщику, расширение `pg_trgm` должно быть в списке разрешённых —
у большинства оно есть, но проверить это нужно **до** переноса,
а не после.

Симптом: миграция падает с `permission denied to create extension`.

### Размер тела запроса

Кураторы загружают материалы через приложение (ADR-0016), и самый
щедрый предел — **50 МБ** (минусовка). Посредник перед приложением
должен пропускать такое тело.

Traefik по умолчанию тело не ограничивает — специально настраивать
нечего. Если перед ним стоит nginx, ему нужно:

```nginx
client_max_body_size 50m;
```

Симптом неверной настройки узнаваем: маленькие файлы загружаются,
а минусовки обрываются на середине с ошибкой «сервер ответил непонятно».

## 4. Проверка, что всё работает

| Что проверить       | Как                                                                           |
| ------------------- | ----------------------------------------------------------------------------- |
| Платформа отвечает  | `curl https://ваш-домен/api/health` → `{"status":"ok"}`                       |
| База доступна       | тот же адрес: при недоступной базе вернётся 503                               |
| Фоновые задачи живы | в журнале контейнера `worker` каждые 5 минут строка «фоновые задачи работают» |

Последний пункт важен: без этой строки задача сверки подписок может
не выполняться неделями, и никто не заметит, пока участники не начнут
жаловаться на пропавший доступ.

## 5. Резервные копии

### Настройка

На сервере, раз в сутки:

```
0 3 * * * DATABASE_URL="..." S3_BUCKET="..." S3_ENDPOINT="..." /путь/scripts/db-backup.sh
```

Копия складывается локально и отправляется в S3. Локальные старше семи дней
удаляются автоматически.

Скрипт отказывается считать копию удачной, если выгрузка не удалась,
получилась подозрительно маленькой или не содержит ни одной таблицы.
Это защита от самой неприятной ситуации: исправный на вид архив
с пустым содержимым, который обнаруживается в день, когда он понадобился.

### Восстановление

```bash
DATABASE_URL="..." ./scripts/db-restore.sh /var/backups/guitar-club/guitar-club_2026-08-07_03-00.sql.gz
```

Скрипт спросит подтверждение: он полностью замещает содержимое базы.

### ⚠️ Учения — обязательно

**Резервная копия, которую ни разу не разворачивали, резервной копией
не является.**

Раз в квартал:

1. Взять свежую копию.
2. Развернуть её на отдельной базе (не на боевой!).
3. Проверить: таблицы на месте, участники на месте, права на месте.
4. Записать дату проверки.

Порядок отработан при разработке: база стиралась полностью и поднималась
из копии, все данные восстанавливались корректно.

## 6. Откат неудачного обновления

**Через Dokploy:** в истории развёртываний выбрать предыдущее, нажать
«Откатить». Занимает около минуты.

**Важно про базу:** откат кода не откатывает миграции. Если новая версия
изменила структуру базы, а старая с ней не работает — сначала
восстанавливайте базу из копии, потом откатывайте код.

Именно поэтому миграции пишутся так, чтобы старая версия кода продолжала
работать: новые колонки добавляются необязательными, старые удаляются
не сразу, а через версию.

## 7. Что делать, когда что-то сломалось

### Платформа не открывается

1. Журнал контейнера `app` — обычно там прямо написана причина.
2. Частая причина после обновления настроек: приложение не запустилось
   из-за неверной переменной. В журнале будет список того, что не так.
3. Если журнал пуст — проверить, что контейнер вообще запущен.

### Участники жалуются на пропавший доступ

1. Проверить журнал контейнера `worker`: идут ли задачи.
2. Проверить, что бот всё ещё администратор закрытого канала.
3. Крайняя мера: выдать доступ вручную через раздел «Подписки»
   (появится на Этапе 9).

Напоминание: недоступность Telegram сама по себе доступ не отбирает —
платформа доверяет последнему известному состоянию.

### Кончилось место на диске

Чаще всего — старые образы Docker:

```bash
docker system prune -a --volumes=false
```

`--volumes=false` обязателен: без него удалятся данные базы.

## 9. Чего делать нельзя

- **Запускать `pnpm db:reset` на боевом сервере.** Скрипт защищён проверкой,
  но лучше просто не пытаться.
- **Править данные напрямую в базе.** Изменения мимо приложения не попадут
  в журнал действий, и разобраться потом будет невозможно.
- **Хранить секреты в репозитории.** Только в настройках развёртывания.
- **Публиковать порт базы наружу.** К ней обращаются только контейнеры
  из той же сети.
