# ADR-0013. Страница песни: выбор варианта и выдача файлов

**Статус:** принято · **Дата:** 2026-08 · **Шаг:** 5.3

## Контекст

Страница разбора — второй по посещаемости экран платформы и единственный,
на котором человек проводит час с гитарой в руках. На ней сходятся три
задачи, каждая со своим решением:

1. какой из нескольких вариантов разбора открыть;
2. как отдать участнику табы, не создавая постоянной ссылки на файл;
3. кто видит неопубликованное.

Третий вопрос при разработке оказался связан с ошибкой шага 5.2 и разобран
в отдельном разделе.

## Решение 1. Уровень и вариант живут в адресе

`?level=intermediate`, а при нескольких разборах одного уровня —
дополнительно `?v=<id>`.

Схема данных намеренно допускает два разбора одного уровня от разных
кураторов (ADR-0012), поэтому уровень не является ключом. Одного параметра
не хватило бы, а замена его на идентификатор сделала бы адрес нечитаемым
и ломала бы ссылки при пересоздании разбора.

**Что это даёт.** Ссылку на конкретный уровень пересылают в чат клуба —
и она открывает именно его. Работает кнопка «назад», страница собирается
на сервере, JavaScript не нужен.

**Цена.** Переключение уровня — переход страницы, а не мгновенная замена
блока. При серверной сборке это не заметно, а состояние плеера на шаге 5.4
всё равно пришлось бы сбрасывать при смене варианта.

### Правила выбора

Порядок предпочтений — от самого явного намерения к самому слабому:
вариант из адреса, уровень из адреса, уровень из профиля, самый простой
из имеющихся.

Два правила заслуживают отдельного упоминания, потому что оба неочевидны
и оба выведены из живых случаев:

- **Уровень из адреса применяется только точным совпадением.** Если человек
  перешёл по ссылке «продвинутый разбор», а у песни такого нет, подменять
  его ближайшим нельзя: человек примет разбор для начинающих за продвинутый
  и решит, что клуб торгует ерундой. Возврат к подбору по профилю честнее.
- **При подборе по профилю ближайший уровень берётся в сторону упрощения.**
  Разобрать песню ниже своего уровня скучно, но возможно; выше —
  невозможно, и человек уходит со страницы.

Выбор вынесен в чистые функции (`arrangement-selection.ts`) и покрыт
тестами: живых случаев пять, и ошибка в любом даёт пустой экран вместо
разбора.

## Решение 2. Файлы отдаются обработчиком адреса, а не действием сервера

Скачивание — это переход по ссылке, а не изменение данных. Обычная ссылка
работает без JavaScript, открывается в новой вкладке, копируется
и правильно объявляется экранным диктором; действие сервера потребовало бы
кода в браузере ради того, что браузер умеет сам.

```
GET /api/media/[id]/download
  → есть ли сессия            нет → на вход, с возвратом сюда
  → можно ли скачивать вид    видео и внешние табы — никогда
  → обработан ли файл         нет → понятное объяснение
  → оплачена ли подписка      нет → на страницу продления
  → подписанная ссылка на 15 минут → 302
```

**Файл через наш сервер не проходит.** Мы проверяем права и отвечаем
перенаправлением на хранилище. Поэтому четырёх гигабайт памяти хватит
при любом объёме скачиваний (ARCHITECTURE §2).

**Ключ объекта наружу не уходит никогда.** В разметке страницы лежит
идентификатор материала, а не путь к файлу: постоянного адреса у закрытых
материалов не существует по определению, иначе пересылка ссылки в чужой
чат снова стала бы возможной.

**Ошибки ведут туда, где человек может что-то сделать.** «403 Forbidden»
в ответ на нажатие «Скачать табы» не объясняет ничего и никуда не ведёт.

### Побочное следствие: имя скачиваемого файла

Хранилище получило необязательный параметр подписи — имя, под которым файл
сохранится. Без него участник скачивает пять табов и получает пять файлов
вида `a3f21c-1.pdf`, различить которые невозможно. Имя входит в подпись,
поэтому подменить его правкой адреса нельзя.

## Решение 3. «Видит ли черновики» приходит сверху

**Это исправление ошибки шага 5.2, найденной при разработке.**

Режим «смотреть как участник» (шаг 3.2) на каталоге разборов не работал.
Маска режима накладывается в слое приложения, а модуль разборов спрашивал
права напрямую, вызовом `can`, — и получал настоящие. Куратор, включивший
режим, продолжал видеть черновики: ровно то, ради предотвращения чего
режим и сделан.

Исходное рассуждение («пусть сервис решает сам, тогда страница не забудет»)
было верным по намерению и неверным по исполнению: надёжность достигалась
тем, что решение принимается в одном месте, — но местом был выбран слой,
который не знает о режиме и знать не может, потому что тот же код работает
в процессе фоновых задач, где браузера нет.

**Новая схема.** Модули содержимого принимают `ContentViewer` —
`{ userId, canSeeDrafts }`. Собрать эту структуру можно единственным
способом: helper `getContentViewer` в слое приложения. Прямое обращение
к правам оттуда запрещено правилом линтера, которое существует с шага 3.2.

Гарантия при этом не ослабла, а усилилась: раньше неверный вызов тихо
работал не так, теперь он не собирается. Тип общий для всех разделов —
курс, эфиры и новости получат его без обсуждения.

## Что сознательно не сделано

**Нерабочих кнопок на странице нет.** Ни избранного, ни заметок, ни кнопки
«Режим репетиции», ни «Редактировать разбор». Каждая появится со своим
шагом. Кнопка, которая ничего не делает, обучает человека не нажимать
кнопки, и вернуть доверие дороже, чем подождать.

**Прогресс не показывается даже заглушкой.** Учёта прогресса не существует
до Этапа 10; фирменный индикатор `ProgressMarker` под него уже сделан
и ждёт настоящих данных. Число «3 из 6», взятое из воздуха, — это не
демонстрация, а ложь в интерфейсе.

**Место под плеер занято плашкой с заданными пропорциями.** Пустота наверху
страницы читается как поломка вёрстки, а заданный кадр гарантирует, что
подключение видеохостинга на шаге 5.4 не сдвинет всю страницу.

## Последствия

- Появился общий тип `ContentViewer` в `shared/content` — его примут все
  разделы содержимого.
- Модуль `media` из одной схемы превратился в рабочий: правила, чтение,
  выдача ссылок. Шаг 5.4 добавит к нему видео, не трогая файлы.
- Дизайн-система получила `PillLink` и `PropertyList`; одинаковая
  «таблетка», скопированная в трёх местах каталога, стала одной.
- Изменена подпись трёх функций сервиса разборов. Обратная совместимость
  внутри проекта не нарушена: внешнего API у платформы нет.
